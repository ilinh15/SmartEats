# 🔐 Authentication System Setup Guide

## Overview
This guide covers the complete authentication flow for Tasteful Journeys:
- **LoginPage** - User login with email/password
- **RegisterPage** - New user registration 
- **PreferencePage** - Food preference selection after registration
- **Firebase Integration** - User data stored in Firestore

---

## 🚀 Quick Start

### 1. Firebase Project Setup

#### Step 1: Create Firebase Project
1. Go to [Firebase Console](https://console.firebase.google.com)
2. Click "Add project"
3. Enter project name (e.g., "Tasteful Journeys")
4. Click through the setup wizard
5. Wait for project creation

#### Step 2: Enable Authentication
1. In Firebase Console, go to **Authentication**
2. Click **Get Started**
3. Click **Email/Password** provider
4. Enable "Email/Password" 
5. Enable "Email link (passwordless sign-in)" (optional)
6. Click **Save**

#### Step 3: Create Firestore Database
1. In Firebase Console, go to **Firestore Database**
2. Click **Create Database**
3. Select **Start in test mode** (for development)
4. Choose your location (e.g., us-central1)
5. Click **Create**

#### Step 4: Get Firebase Config
1. Go to **Project Settings** (gear icon)
2. Click **Your apps** tab
3. Select **Web** (or create if not exists)
4. Copy the Firebase config object

### 2. Configure Environment Variables

Create `.env.local` file in project root:

```bash
VITE_FIREBASE_API_KEY=your_api_key
VITE_FIREBASE_AUTH_DOMAIN=your_project.firebaseapp.com
VITE_FIREBASE_PROJECT_ID=your_project_id
VITE_FIREBASE_STORAGE_BUCKET=your_project.appspot.com
VITE_FIREBASE_MESSAGING_SENDER_ID=your_sender_id
VITE_FIREBASE_APP_ID=your_app_id
```

**Do NOT commit `.env.local` to version control!**

### 3. Install Dependencies

Your project should already have Firebase installed:

```bash
npm install firebase
# or
bun install firebase
```

## 📊 Firestore Database Structure

After successful registration, users are stored with this structure:

```
Collection: users
Document ID: {user.uid}  // Auto-generated by Firebase Auth
Fields:
├── username: string              (e.g., "john_doe")
├── email: string                 (e.g., "john@example.com")
├── preferences: array<string>    (e.g., ["Vegan", "Gluten-free"])
└── createdAt: string             (ISO timestamp)
```

Example Firestore document:
```json
{
  "username": "foodlover123",
  "email": "foodlover@example.com",
  "preferences": ["Halal", "Vegan", "Low-carb"],
  "createdAt": "2024-04-08T10:30:00.000Z"
}
```

## 🔒 Security Rules (Firestore)

For **test mode** (development), anyone can read/write.

For **production**, implement proper rules:

```javascript
// Firestore Security Rules
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{userId} {
      // Users can only read/write their own data
      allow read, write: if request.auth.uid == userId;
    }
  }
}
```

**Set in Firebase Console:**
1. Go to **Firestore Database**
2. Click **Rules** tab
3. Paste the rules above
4. Click **Publish**

## 💻 Code Examples

### Access Current User

```tsx
import { getAuth } from "firebase/auth";
import { useEffect, useState } from "react";

export function MyComponent() {
  const [user, setUser] = useState(null);
  const auth = getAuth();

  useEffect(() => {
    const unsubscribe = auth.onAuthStateChanged((currentUser) => {
      setUser(currentUser);
    });
    return unsubscribe;
  }, [auth]);

  if (user) {
    return <p>Welcome, {user.email}</p>;
  }
  return <p>Not logged in</p>;
}
```

### Get User Preferences

```tsx
import { getFirestore, doc, getDoc } from "firebase/firestore";
import { getAuth } from "firebase/auth";

export async function getUserPreferences() {
  const auth = getAuth();
  const db = getFirestore();
  const user = auth.currentUser;

  if (!user) return null;

  const docSnap = await getDoc(doc(db, "users", user.uid));
  return docSnap.data();
}
```

### Logout

```tsx
import { getAuth, signOut } from "firebase/auth";

export async function logout() {
  const auth = getAuth();
  await signOut(auth);
  // Redirect to login
  window.location.href = "/login";
}
```

## 🐛 Troubleshooting

### "Firebase Config is not defined"
**Solution:** Ensure `.env.local` has all required variables and restart dev server

### "Cannot read property 'uid' of null"
**Solution:** User is not authenticated. Check if credentials are correct.

### "Permission denied" when writing to Firestore
**Solution:** Check Firestore rules. Use test mode or update rules to allow writes.

### "Email already in use"
**Solution:** User already registered. Direct them to login page.

## 🔐 Security Checklist

- ✅ Firebase config uses environment variables (not hardcoded)
- ✅ Passwords must be 6+ characters
- ✅ Email validation on both client and Firebase
- ✅ Test mode rules will be replaced with production rules
- ✅ User data only accessible to authenticated users
- ✅ Session storage cleared after preference setup

## 💡 Tips & Best Practices

1. **Always use HTTPS** in production
2. **Never commit .env.local** to git
3. **Test authentication thoroughly** before deployment
4. **Implement password reset** for better UX
5. **Add logout endpoint** to home page
6. **Monitor Firebase usage** to avoid unexpected costs
7. **Use Firestore indexes** for better query performance
8. **Implement rate limiting** to prevent brute force attacks
